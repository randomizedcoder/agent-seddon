## Decisions log (append-only)

- 2026-09-28 — CP-05 splits the driver: the pure tick (`agent_campaign::driver`) over seams
  (`CampaignBackend` in `agent_core::campaign` beside `CampaignStore`, since testkit must not
  depend on agent-campaign; `TickPlanner`, `PrPoller`, `WorkerExec`) + a thin
  `agent_runtime::campaign_driver::build_driver`, so T11 runs on `MemCampaigns` with doubles.
- 2026-09-28 — The shipped CP-05 driver has **no exec**, so its claim phase is off: `fail`
  blocks dependents and rolls parents to `blocked`, and a stub that failed every leaf would
  wreck CP-04's `add → run --once → show`. `run --once` prints `claimed 0  dispatched 0
  (workers: CP-06)`.
- 2026-09-28 — Subprocess dispatch is CP-06's: handing the owner token through the environment
  needs a new `ExecSpec.env_set` across agent-core / agent-sandbox / agent-grpc / agent-proto
  (`EnvPolicy` is only `Inherit | Scrub`), dead plumbing without an exec. CP-05 lands the
  `sandbox` key (validated, unused) and the `--run-task` stub (exit 3 without / unsafe
  `AGENT_CAMPAIGN_OWNER`, before the config is read; exit 4 with it).
- 2026-09-28 — Tenant discovery is `CampaignBackend::tenants()` over the `tasks` table (states
  `ready, decomposing, claimed, running, in_review`), not the config store's `tenants()` (cards,
  which campaigns never write) nor the shared `tenants` table (config-only tenants). Resident:
  `Discover` iff `[tenancy] per_tenant`, else `Fixed(["local"])`; `--tenant T` ⇒ `Fixed([T])`.
- 2026-09-28 — The `decomposing` reaper is a new seam method `reap_decomposing(max_age_secs)`
  with its own transition row (`decomposing → ready | objective, task | reaper`, T2 84) rather
  than an extension of `reap()`: `Reaped.lost_owner` is non-optional and T6 pins it; the bound
  is the constant `DECOMPOSING_MAX_SECS = 900` (a per-policy bound would need a JSONB root join
  for little gain), clamped like a lease; no attempt is closed (the planner's row lives in the
  finishing transaction). A planner still alive past the bound loses its CAS and writes nothing.
- 2026-09-28 — The poll phase is a `PrPoller` seam with `NoopPoller` (zeros, no store call) and
  the const `POLL_BATCH = 20` until `poll_batch` lands with the forge poller (CP-06);
  `positive_phase_order` observes the phase through a recording poller.
- 2026-09-28 — `agent campaign run` (resident) is gated by `[campaign] enabled` at the CLI (after
  the config load, before any store opens, naming the key) and in `Driver::tick`
  (`TickReport::disabled()`, zero store calls); `run --once` ignores the key (an explicit human
  action) and forces `enabled` on its driver.
- 2026-09-28 — Each tenant's phases run under `scope(SessionKey::parse(tenant, "campaign"))`
  (mirroring the scheduler driver) so provider calls attribute to the tenant; actors are typed
  inside the stores. Tracing only (`campaign.tick` span + one `info!`); metrics are CP-08.
- 2026-09-28 — A worker runs under `tokio::time::timeout` on its own spawned task (`AbortOnDrop`)
  so a panic is a `JoinError` the outer task settles; permits are held through the settle write;
  `adversarial_worker_hangs` is a `start_paused` test (`tokio` `test-util` dev feature).
- 2026-09-28 — Deviation from `04-executor.md`: the tick does **not** join its workers (a leaf may
  run `worker_timeout_secs`; blocking the tick would stop reaping and planning). The `JoinSet` and
  both semaphores persist on the `Driver`; each tick harvests finished workers first; the claim
  limit is `min(per-tenant free permits, global budget)` so acquisition never waits; `drain()` is
  for once-mode, tests and shutdown; `ClaimRequest.lease_secs = Policy::default().lease_secs`
  (a batch spans campaigns; the per-campaign lease is the CP-06 heartbeat's). Recorded in 04.

- 2026-09-26 — Everything pure (`allowed()`, `rollup()`, `TaskPath`, `Policy`, the seam) lives in
  `agent_core::campaign`; `agent-testkit` must not depend on `agent-campaign` (impl crates
  dev-depend on testkit, never the reverse). `agent-campaign` holds display letters now and the
  Postgres tier in CP-02.

  (`decompose` / `mark_leaf` / `plan_close`), never at `plan_start` (protocol (b) step 1; T5
  `negative_version_conflict`).

- 2026-09-26 — JSONB is bound as TEXT with `::jsonb` casts and read as `::text`; the sqlx `json`
  feature stays off.
- 2026-09-26 — `IdemKey` is validated by the store (64 lowercase hex) and computed by the planner
