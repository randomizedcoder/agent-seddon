# 01 — Schema: one tree table, two audit tables

Crate `agent-campaign`, migration `0001_campaigns.sql`, runner copied from `PgDigests`
(`crates/agent-digest/src/postgres.rs:44-119`): embedded `MIGRATIONS: &[(i64, &str)]`,
`pg_advisory_xact_lock` on a crate-specific key, ledger table `_campaign_migrations`,
`connect` / `connect_lazy` / `from_pool`. sqlx 0.8 without `macros` or `migrate`
(`Cargo.toml:144`), so every statement is a string and every column is read by name.

## Path grammar

```
path      := root ( '.' ordinal ){0,6}
root      := [1-9][0-9]*            -- the campaign's own task_id, as text
ordinal   := [1-8]                  -- position under the parent, 1-based
depth     := number of '.' in path  -- 0 for the root, ≤ 6
```

`path` is computed by the store under the parent's row lock as
`parent.path || '.' || next_ordinal` and never accepted from a caller. Display maps the root to
a letter per listing (`A`, `A.1`, `A.1.3`), never stored. The regex in the CHECK below is the
storage grammar; the Rust parser (`agent_campaign::path`, CP-01) is the same grammar and is the
only thing that may build a `LIKE` pattern from a path.

## DDL

```sql
-- 0001_campaigns.sql
CREATE TABLE IF NOT EXISTS tenants (tenant TEXT PRIMARY KEY);   -- shared with the other tiers

CREATE TABLE tasks (
  tenant        TEXT        NOT NULL REFERENCES tenants(tenant),
  task_id       BIGINT      GENERATED BY DEFAULT AS IDENTITY,
  campaign_id   BIGINT      NOT NULL,                 -- the root's task_id; on the root = task_id
  repo_id       BIGINT      NOT NULL,                 -- FK to repos(tenant, repo_id), see below
  parent_id     BIGINT,                               -- NULL iff depth = 0
  path          TEXT        NOT NULL,                 -- '1042' | '1042.1' | '1042.1.3'
  depth         SMALLINT    NOT NULL CHECK (depth BETWEEN 0 AND 6),
  ordinal       SMALLINT    NOT NULL CHECK (ordinal BETWEEN 1 AND 8),
  kind          TEXT        NOT NULL CHECK (kind IN ('objective', 'task', 'leaf')),
  state         TEXT        NOT NULL CHECK (state IN (
                  'draft', 'awaiting_approval', 'ready', 'decomposing', 'decomposed',
                  'claimed', 'running', 'in_review', 'blocked', 'done', 'failed',
                  'cancelled', 'superseded')),
  title         TEXT        NOT NULL CHECK (length(title) BETWEEN 1 AND 120),
  goal          TEXT        NOT NULL CHECK (length(goal) BETWEEN 1 AND 4000),  -- model-written below the root
  acceptance    JSONB       NOT NULL DEFAULT '[]',    -- ≤ 6 strings, each ≤ 300 chars (app-side)
  touches       JSONB       NOT NULL DEFAULT '[]',    -- ≤ 12 node_keys or repo paths (app-side)
  depends_on    BIGINT[]    NOT NULL DEFAULT '{}',    -- sibling task_ids; acyclic (app-side)
  est_size      TEXT        CHECK (est_size IN ('xs', 's', 'm', 'l')),
  source_ref    TEXT        CHECK (source_ref IS NULL OR length(source_ref) <= 120),  -- 'gap:SI-4', 'issue:123'
  policy        JSONB       CHECK (policy IS NULL OR depth = 0),
  version       BIGINT      NOT NULL DEFAULT 1,
  attempts      SMALLINT    NOT NULL DEFAULT 0,       -- planner attempts on this node
  claimed_by    TEXT,                                 -- driver owner token while claimed / running
  lease_until   TIMESTAMPTZ,
  pr_number     BIGINT,
  pr_url        TEXT        CHECK (pr_url IS NULL OR length(pr_url) <= 512),
  branch        TEXT        CHECK (branch IS NULL OR length(branch) <= 128),
  superseded_by BIGINT,
  created_by    TEXT        NOT NULL,                 -- 'user:<principal>' | 'model:<attempt_id>'
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (tenant, task_id),
  FOREIGN KEY (tenant, parent_id)   REFERENCES tasks (tenant, task_id),
  FOREIGN KEY (tenant, campaign_id) REFERENCES tasks (tenant, task_id) DEFERRABLE INITIALLY DEFERRED,
  UNIQUE (tenant, path),
  CHECK ((depth = 0) = (parent_id IS NULL)),
  CHECK (path ~ '^[1-9][0-9]*(\.[1-8]){0,6}$'),
  CHECK (array_length(string_to_array(path, '.'), 1) = depth + 1),
  CHECK ((state IN ('claimed', 'running')) = (claimed_by IS NOT NULL)),
  CHECK ((state IN ('claimed', 'running')) = (lease_until IS NOT NULL)),
  CHECK (kind <> 'objective' OR depth = 0),
  CHECK (depth <> 0 OR kind = 'objective'),
  CHECK (depth <> 0 OR campaign_id = task_id),
  CHECK (superseded_by IS NULL OR state = 'superseded')
);

CREATE INDEX tasks_subtree  ON tasks (tenant, path text_pattern_ops);
CREATE INDEX tasks_ready    ON tasks (tenant, repo_id, campaign_id, path)
  WHERE state = 'ready' AND kind = 'leaf';
CREATE INDEX tasks_plan     ON tasks (tenant, campaign_id, path)
  WHERE state = 'ready' AND kind <> 'leaf';
CREATE INDEX tasks_lease    ON tasks (tenant, lease_until) WHERE claimed_by IS NOT NULL;
CREATE INDEX tasks_review   ON tasks (tenant, updated_at) WHERE state = 'in_review';
CREATE INDEX tasks_parent   ON tasks (tenant, parent_id);
CREATE INDEX tasks_campaign ON tasks (tenant, campaign_id);

CREATE TABLE task_events (
  tenant     TEXT        NOT NULL REFERENCES tenants(tenant),
  event_id   BIGINT      GENERATED ALWAYS AS IDENTITY,
  task_id    BIGINT      NOT NULL,
  from_state TEXT,                                    -- NULL on creation
  to_state   TEXT        NOT NULL,
  actor      TEXT        NOT NULL,                    -- 'user:<p>' | 'driver:<owner>' | 'model:<attempt>' | 'reaper' | 'poller'
  version    BIGINT      NOT NULL,                    -- tasks.version after the write
  detail     JSONB       NOT NULL DEFAULT '{}' CHECK (pg_column_size(detail) <= 4096),
  at         TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (tenant, event_id),
  FOREIGN KEY (tenant, task_id) REFERENCES tasks (tenant, task_id)
);
CREATE INDEX task_events_task ON task_events (tenant, task_id, event_id);

CREATE TABLE task_attempts (
  tenant      TEXT        NOT NULL REFERENCES tenants(tenant),
  attempt_id  BIGINT      GENERATED ALWAYS AS IDENTITY,
  task_id     BIGINT      NOT NULL,
  kind        TEXT        NOT NULL CHECK (kind IN ('decompose', 'work')),
  idem_key    TEXT        NOT NULL CHECK (length(idem_key) = 64),  -- hex sha256
  prompt_hash TEXT        NOT NULL DEFAULT '',
  model       TEXT        NOT NULL DEFAULT '',
  tokens_in   BIGINT      NOT NULL DEFAULT 0 CHECK (tokens_in >= 0),
  tokens_out  BIGINT      NOT NULL DEFAULT 0 CHECK (tokens_out >= 0),
  session_id  TEXT,
  owner       TEXT,                                   -- driver owner token for kind = 'work'
  outcome     TEXT        NOT NULL CHECK (outcome IN (
                'pending', 'execute', 'split', 'needs_info', 'reject',
                'pr', 'error', 'timeout', 'lease_lost')),
  pr_url      TEXT        CHECK (pr_url IS NULL OR length(pr_url) <= 512),
  error       TEXT        CHECK (error IS NULL OR length(error) <= 2000),
  started_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  ended_at    TIMESTAMPTZ,
  PRIMARY KEY (tenant, attempt_id),
  UNIQUE (tenant, idem_key),
  FOREIGN KEY (tenant, task_id) REFERENCES tasks (tenant, task_id)
);
CREATE INDEX task_attempts_task ON task_attempts (tenant, task_id, attempt_id);

-- Conditional FK to the repo-knowledge `repos` table (RK-02). The migration is
-- re-runnable: the constraint is added once `repos` exists and skipped otherwise.
DO $$
BEGIN
  IF to_regclass('repos') IS NOT NULL
     AND NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = 'tasks_repo_fk') THEN
    ALTER TABLE tasks ADD CONSTRAINT tasks_repo_fk
      FOREIGN KEY (tenant, repo_id) REFERENCES repos (tenant, repo_id);
  END IF;
END $$;
```

The `DEFERRABLE INITIALLY DEFERRED` self-reference on `campaign_id` lets the root insert refer
to its own not-yet-committed `task_id` in one statement (protocol (a) in
[`02-transactions.md`](02-transactions.md)). Children never need it: their root already exists.

As built (CP-02, `crates/agent-campaign/migrations/0001_campaigns.sql`), with two deliberate
differences from the listing above: every `CREATE TABLE` / `CREATE INDEX` is `IF NOT EXISTS`, so
a database carrying the schema but no ledger re-records the baseline harmlessly (the digest and
config-store runners do the same), and the two UNIQUE constraints are **named** —
`tasks_path_key (tenant, path)` and `task_attempts_idem_key (tenant, idem_key)` — so the store
maps a violation by constraint name (`AlreadyApplied` for the idempotency key), never by message
text. `tenants` is the config-store definition verbatim; whichever runner comes first creates it.
Any suite that `TRUNCATE`s `tenants` must `CASCADE` now that three more tables reference it.

## Invariants

| Invariant | Enforced by |
|---|---|
| `depth = 0 ⇔ parent_id IS NULL ⇔ kind = 'objective' ⇔ campaign_id = task_id` | CHECK |
| `path` matches the grammar; segment count = `depth + 1`; `ordinal ∈ 1..8` | CHECK |
| `(tenant, path)` unique | UNIQUE |
| `path = parent.path || '.' || ordinal`, `depth = parent.depth + 1`, `campaign_id = parent.campaign_id`, `repo_id = parent.repo_id` | app-side under `FOR UPDATE` on the parent; invariant query `tasks_invariants()` in the live suite (T15) |
| ≤ 8 children per parent, live plus superseded | app-side count under the parent lock; the ordinal CHECK makes a ninth impossible to name |
| ≤ `policy.max_nodes` rows per campaign; ≤ `policy.max_depth` | app-side under the parent lock, from the root's policy read in the same transaction |
| `depends_on ⊂ siblings`, no self, acyclic | app-side at decompose time (the only writer of `depends_on`); invariant query |
| `kind = 'leaf' ⇒ no children` | app-side: `mark_leaf` requires zero children; decompose requires `kind <> 'leaf'` |
| exactly one non-NULL `policy` per campaign, on the root | CHECK (`depth = 0`) + roots always carry one |
| `claimed_by` and `lease_until` present ⇔ `claimed` / `running` | CHECK |
| `superseded_by` set ⇔ `superseded` | CHECK |
| every state change has a `task_events` row with the new `version` | store helper `transition()`; invariant query joins `max(version)` per task to the last event |
| `version` strictly increases by 1 per write | every UPDATE is `SET version = version + 1 WHERE version = $expected` and checks `rows_affected = 1` |

`tasks_invariants()` is a plain SQL query kept in the test crate, run after every live-suite
case; it returns the offending rows and the suite asserts an empty result.

## `policy` JSON

Stored on the root only, validated by a `#[serde(deny_unknown_fields)]` struct at creation and
on every human edit, defaults filled in before the snapshot is written:

```json
{
  "approve_levels": [1],
  "require_pr_approval": true,
  "draft_prs": true,
  "max_depth": 6,
  "max_children": 8,
  "max_nodes": 200,
  "max_plan_attempts": 3,
  "max_plan_tokens": 400000,
  "max_worker_tokens_per_leaf": 2000000,
  "auto_replan": false,
  "lease_secs": 1800
}
```

Ranges: `max_depth ∈ 1..=6`, `max_children ∈ 1..=8`, `max_nodes ∈ 1..=200`,
`max_plan_attempts ∈ 1..=10`, `lease_secs ∈ 60..=86400`, every `approve_levels` entry
`∈ 1..=max_depth`. The struct's ranges are the table CHECKs' ranges; a policy cannot loosen a
CHECK.

## Other columns

- `acceptance`: JSON array of strings, ≤ 6 items, each ≤ 300 chars, screened for injection.
- `touches`: JSON array of strings, ≤ 12 items; each is a repo-knowledge `node_key`
  (`rust:fn:agent_core::security::confine`) or a repo-relative path that passes `safe_segment`
  per segment. Never a glob.
- `source_ref`: root only by convention (`'gap:SI-4'`, `'issue:123'`, `'doc:docs/design/x'`).
- `created_by`: `'user:<principal>'` for the root and for human edits; `'model:<attempt_id>'` for
  children written by protocol (b).

## Size

A campaign is ≤ 200 rows by policy; events run about five per task; attempts one to three per
task. Ten thousand campaigns is a few million small rows. No partitioning; the tenant-led indexes
are sufficient.
